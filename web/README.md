# web

The LAN BUNKER site: Astro 7, server rendered on Cloudflare Workers, Tailwind 4.
The root `README.md` describes the whole repository. This file covers the site.

## Commands, from `web/`

| Command          | Action                                                         |
| ---------------- | -------------------------------------------------------------- |
| `pnpm dev`       | Dev server on `localhost:4321`. It talks to the API on `:3000` |
| `pnpm build`     | Production build into `dist/`                                  |
| `pnpm typecheck` | TypeScript 7 over every `.ts` and `.tsx`. Under a second       |
| `pnpm check`     | `astro check`. The only checker that reads `.astro`            |
| `pnpm lint`      | oxlint                                                         |
| `pnpm fmt`       | oxfmt, which writes. `pnpm fmt:check` only reads               |
| `pnpm e2e`       | Playwright against a fresh API and the dev site                |

From the repository root, `make web-check` formats, then runs both type checks,
the lint and the build. It leaves the tree formatted, so a save in the editor
changes nothing afterwards. `make web-e2e` runs the browser tests, and
`make web-fmt` formats alone.

## Formatting

Two formatters, one style. `oxfmt` owns every file type it can parse.
`prettier` owns `.astro`, which oxfmt cannot parse, through
`prettier-plugin-astro`. Their settings match: no semicolons, double quotes,
trailing commas, width 90, and arrow parameters without parentheses. Astro keeps
a two space indent, everything else four.

The editor uses the same pair. `.vscode/settings.json` points `.astro` at the
Astro extension, which reads `web/.prettierrc.json`, and every other type at the
oxc extension, which reads `web/.oxfmtrc.json`. A save and the checklist produce
the same bytes.

## Structure

```
src/pages/              one file per route, /admin is the backoffice
src/actions/            form handlers: accounts and admin in index.ts, tournaments in tournaments.ts
src/middleware.ts       session cookie to Astro.locals, forced password change, posted form fields
src/lib/api.ts          the typed client and the call wrappers every page and action uses
src/lib/api-types.d.ts  generated by `make api-types`, never edited by hand
src/lib/action.ts       turns an API failure into the matching ActionError
src/lib/form.ts         turns an ActionError into one sentence a page can show
src/lib/schemas.ts      the zod rules every form posts against
src/lib/session.ts      the logged-in player and their token, as one value
src/lib/detail.ts       parses the tournament detail the kiosk polls over the wire
src/components/ui/      Alert, Button, Panel, Kv, Badge, Prompt, Pager, Glyph, Countdown
src/components/*.tsx    React islands: BracketView, LiveBracket, BracketEditor, GlyphMark
src/layouts/            Layout for the site, AdminLayout for the backoffice
src/content/            events and the about page, as Markdown
e2e/                    Playwright tests, with the shared helpers in support.ts
```

## Calling the API

No page and no action calls `fetch` or the client directly. Every call goes
through `call` or `callEmpty` in `src/lib/api.ts`. Both answer an `ApiResult`
and neither throws, so a dead API is a value the page renders and never a 500.

A page reads the value with `dataOf`, the failure with `failureOf`, and turns a
missing row into a 404 with `isMissing`. An action unwraps with `unwrap`, which
throws the `ActionError` that matches the code the API sent.

## Errors on a page

Astro reports a refused form input as an `ActionInputError` whose `message` is
the whole issue list as JSON. No page renders that. Every failure goes through
the `Alert` component, which reads the field messages back and shows one
sentence. `e2e/errors.spec.ts` asserts that no message is ever a JSON blob.

The middleware keeps the fields of a posted form in `Astro.locals.submitted`,
minus anything that looks like a password, so a refused form can fill itself in
again. A player who mistypes one field keeps what they typed in the others.

## Type checking

Two checkers run, and both must pass.

`pnpm typecheck` is TypeScript 7, the native compiler. It reads every `.ts` and
`.tsx` file in under a second, so it is the fast gate. It cannot read `.astro`.

`pnpm check` is `astro check`, which is the only tool that type-checks a page.
It needs the TypeScript language service API, which version 7 does not ship yet,
so the `typescript` dependency stays on 6.x and the `tsgo` alias holds 7.x.
Revisit when `@astrojs/check` accepts TypeScript 7.

## Environment

`API_URL` names the Rust API, and `wrangler.jsonc` holds it. **A Worker var beats
the shell in local mode**, so a local run selects a wrangler environment instead
of exporting a variable:

- `CLOUDFLARE_ENV=dev` points at `http://127.0.0.1:3000`. `pnpm dev` sets it.
- `CLOUDFLARE_ENV=e2e` points at `http://127.0.0.1:3999`. Playwright sets it.
- The top level is production. A deploy uses it, with no `--env`.

The `env.e2e` port must match `API_PORT` in `playwright.config.ts`.

## Astro 7 notes

`compressHTML: true` keeps the version 6 compression. The version 7 default
follows JSX whitespace rules, which glue two inline elements that only a line
break separates.

`astro dev` puts itself in the background when it detects an agent, and it takes
a lock on the project. The Playwright web server passes `ASTRO_DEV_BACKGROUND=0`
so it stays in the foreground, and `--ignore-lock` so it starts beside a dev
server that is already running.
